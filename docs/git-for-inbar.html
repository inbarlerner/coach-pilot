מה Git עושה

Git הוא כלי שזוכר כל גרסה של הפרויקט. GitHub הוא האתר שמחזיק את העותק המשותף שלנו בענן. אפשר לחשוב על Git כשילוב של שלושה דברים מוכרים:

נקודות שמירה במשחקכל גרסה נשמרת, ואפשר לחזור לכל אחת מהן.
מעקב שינויים בוורדרואים בדיוק איזו שורה השתנתה, מי שינה ומתי.
תיקייה משותפת, בלי דריסותשתינו עובדות על אותו פרויקט, ו־Git מחבר את השינויים.

ענפים ו־Pull Request: מה קרה עם השינוי של ענבר

ענף הוא עותק צדדי שאפשר לנסות בו דברים בלי לגעת במה שבאוויר. כך עבר השינוי מהרעיון ועד האתר:

  1. ענבר פתחה ענף נפרדעותק צדדי בשם claude/project-thread-aa4ukc. בזמן הזה, main והאתר לא השתנו.
  2. קלוד עבד בענףהוסיף אפשרות למשתמש קיים לבקש להיות מאמן, וכתב לזה בדיקה.
  3. נפתח Pull Request #1בקשה למזג את הענף לתוך main. כאן אפשר לראות את כל השינויים לפני שהם עולים לאתר.
  4. מיזוג לתוך mainהשינוי נכנס לגרסה הראשית, ו־Cloudflare עדכן את האתר החי.
  5. אצל ג׳ני: git pullפקודה אחת הביאה את השינוי למחשב שלה. בלי לשלוח קבצים בווטסאפ.

ומה קורה אם שתינו משנות את אותה שורה?

Git עוצר ומראה את שתי הגרסאות
ג׳ני: מכסת בקשות ברירת מחדל = 3
ענבר: מכסת בקשות ברירת מחדל = 5
ואנחנו (או קלוד) בוחרות מה נשאר

זה נקרא התנגשות (conflict). Git לא מנחש ולא מוחק כלום בשקט. הוא מסמן את המקום ומחכה להחלטה. כדי שזה יקרה כמה שפחות:

  • למשוך (pull) לפני שמתחילות לעבוד
  • לשמור בגרסאות קטנות ותכופות
  • לעבוד בענף ולמזג עם Pull Request

הדוגמה מומצאת, רק להמחשה.

השגרה שלנו

  1. מושכות עדכוניםgit pull, כדי להתחיל מהגרסה האחרונה ב־GitHub.
  2. עובדות עם Claude Codeמסבירות מה רוצים. קלוד קורא את CLAUDE.md ועובד לפי הכללים שלנו.
  3. מריצות בדיקותקלוד מריץ את כל הבדיקות לפני שמירה, לפי מה שכתוב ב־CLAUDE.md.
  4. שומרות ושולחותcommit עם הסבר, ואז push ל־GitHub. לשינוי גדול: ענף ו־Pull Request.
  5. האתר מתעדכןCloudflare מפרסם לבד. אם נוסף קובץ SQL חדש, מריצות אותו ב־Supabase.
